# 端侧 LLM Prompt 调优记录

## 背景

- 模型：Qwen2.5-1.5B-Instruct Q4_K_M（约 1.06GB）→ **同日后升级为 Qwen3.5-2B Q4_K_M（约 1.2GB）**
- 引擎：llama_cpp_dart v0.9.0-dev.9，Metal GPU 加速
- 场景：苏格拉底式追问教练，Dart 端硬编码追问维度轮换

## 迭代过程

### v1 — 简单维度标签注入

```
用户消息格式：追问维度：【原因】\n用户输入
系统提示词：通用苏格拉底教练 + 维度说明
```

**效果**：基本可用，但多轮后易重复追问，模型不理解"不要重复"的抽象指令。

### v2 — 加代码层去重 + 重试

在 Dart 端添加：
- 最长公共子串相似度检测（>60% 判定重复）
- 重复时自动切换维度重试（最多 3 次）
- 逐字流式 yield（模拟打字效果）

**效果**：重复问题减少，但对话质量仍不稳定。

### v3 — 复杂结构化 prompt（失败）

```markdown
## 对话结构
第一条 assistant 消息是开场白...
## 追问维度（看到标签后执行）
- 【原因】→ 问"为什么""是什么让你这样想"...
## 输出要求
## 绝对禁止
```

**问题**：规则太多，1.5B 小模型无法准确执行。用户反馈效果不如 v2。

### v4 — 往用户消息注入开场白背景（失败）

```
用户消息 = "【对话背景】AI 开场时说：...\n【追问维度】XX\n【用户回复】..."
```

**问题**：多层标签让模型困惑——不知道应该回复"对话背景"还是"用户回复"，效果比 v2 更差。

### v5 — `addAssistant` 注入 + few-shot prompt ✅

关键改进：
1. **开场白注入**：改用 `EngineChat.addAssistant()` 将欢迎消息作为 assistant 消息写入 chat 历史——正确利用 ChatML 格式
2. **提示词简化**：精简到约 200 tokens，加入 2 个 few-shot 示例
3. **用户消息格式不变**：保持简洁的 `追问维度：【XX】\n用户输入`

```
chat 历史结构：
  system  → 苏格拉底教练 prompt（few-shot 版）
  assistant → 开场白（addAssistant 注入）
  user    → "追问维度：【原因】\n用户回答"
  assistant → 模型追问
  user    → "追问维度：【假设】\n用户回答"
  ...
```

**效果**：当前最佳版本，追问贴题、不过度重复。

### v6 — 梯度追问策略 + PRD 6 规则对齐 ✅（2026-07-06 新增）

从「固定维度轮换」升级为「梯度追问策略」：

**策略变化**：
```
旧（v5）：5 个维度固定轮换（原因→假设→影响→对比→行动），无论对话深度
新（v6）：4 个阶段梯度升级，随对话自然变深
  - round 1      → exploration（探索：帮用户展开话题）
  - round 2-3    → deepening（深入：追问具体细节或例子）
  - round 4-6    → challenge（挑战：质疑底层假设）
  - round 7+     → summary（总结：引导回顾收获）
  - 短回答 < 20 字 → 自动升级到 deepening（无论当前阶段）
```

**提示词变化**：
- 对齐 PRD 6 条对话规则（新增规则 5「矛盾检测」、规则 6「[SUMMARY] 标记」）
- 移除维度相关说明，简化为「追问方向」标记
- 用户消息格式从 `追问维度：【原因】\n用户输入` 变为 `追问方向：【探索】\n用户输入`

**推理参数调优**：
| 参数 | v5 | v6 |
|------|:--:|:--:|
| temperature | 0.85 | 0.5 |
| topP | 0.92 | 0.85 |
| maxTokens | 256 | 128 |
| repeatPenalty | — | 1.15 |

**新增能力**：
- Token 估算器：`LlamaService.estimateTokens()`，SocraticPrompter 全链路追踪
- 上下文监控：累计 > 1800 tokens 日志警告（llama.cpp KV cache 自动截断）

**效果**：追问更自然——不会从「探索」突然跳到「对比」，而是随对话逐层深入。短回答检测让敷衍回答自动触发具体化追问。

## 核心经验总结

### 1. 小模型（1.5B）提示词原则

| 原则 | 说明 |
|------|------|
| **少即是多** | 规则越少越好，每条规则都是干扰源 |
| **示例优先** | few-shot > 规则描述，模型"照猫画虎"比"读懂规则"强 |
| **Dart 端兜底** | 复杂逻辑（去重、维度轮换）放在代码层，不让模型执行 |
| **格式自然** | 消息格式越接近训练数据中的自然对话，效果越好 |

### 2. 开场白注入的正确姿势

- ❌ 拼进用户消息（破坏消息自然度、模型困惑）
- ✅ `addAssistant()` 写入 chat 历史（符合 ChatML 规范）
- 时机：首轮 `sendMessage()` 触发，用 `_round == 1` 判断

### 3. 去重策略

- 最长公共子串占比（代码实现，正则去标点后对比）
- 阈值 60%：太高漏检、太低误判
- 发现重复 → 切换追问维度重新生成（最多 3 次）

### 4. 后续优化方向

- **✅ 已升级模型**：Qwen2.5-1.5B → Qwen3.5-2B（指令遵循能力更强）
- **✅ 梯度追问策略**：v6 已实现从固定维度轮换升级为探索→深入→挑战→总结的梯度策略
- **对话总结**：长对话后压缩历史，防止上下文溢出
- **用户反馈学习**：收集用户满意度信号用于后续微调
