## 核心问题：布局四角堆叠的完整分析

### 现象

6 个节点全部精确落在 `(0.15, 0.15)` `(0.15, 0.85)` `(0.85, 0.15)` `(0.85, 0.85)` 四个角，同角节点完全重叠。

### 根因链路

```
│
├── 斥力公式: 0.6 / dist
│   └── 单个邻居距离 0.25: 力 ≈ 2.4
│   └── 12 个邻居累计: 远超任何其他力
│
├── 中心引力: (0.5 - x) × 0.15
│   └── 最大约 0.037（在边缘处）
│
├── 结论: 斥力 > 引力 × 60+ 倍
│   └── 第一轮迭代就把所有节点推向墙壁
│
├── 硬 clamp [0.15, 0.85]
│   └── 节点卡在墙壁 → 速度持续堆积 → 永不离开
│   └── 四个角落 = 两个墙面的交点 → 最终归宿
│
└── 反弹机制无效
    └── vx *= -0.4 弹回 → 下一帧又被推出 → 永远震荡在墙面
```

### 反直觉教训

**"强斥力 + 硬边界" 是陷阱。** 直觉上觉得边界越强越安全，但实际上：
- 如果斥力天然就强 → 应该弱化斥力，不是加硬约束
- 硬 clamp 会导致速度堆积 → 节点"黏"在墙上
- 正确的不变量是 `所有力应该大致在同一个量级`

### 最终方案：辐射分布 + 微力

放弃"计算合力 → 迭代收敛"的思路，改为两步法：

```
Step 1 — 确定性辐射分布
  所有节点按等角分布在圆上（圆心 0.5，半径 0.3）
  → 确保天生不重叠、不聚类

Step 2 — 微力调整（100 轮）
  斥力: 0.001 / dist（降低 600 倍）
  引力: dist × 0.01（连线节点小幅靠拢）
  中心引力: 0.01
  力上限: 0.05，强阻尼: 0.7
  → 只做小幅精调，不改变整体形状
```

### 调试方法

当算法行为不符合预期时，最有效的方法是 **print 实际数值而非盲调参数**。本次通过输出 6 个节点的精确坐标，立刻发现全部在四角 → 定位到斥力过强。

## 学习者思考题

### 布局算法

1. **力导向 vs 确定性**：什么时候该用力导向，什么时候该用确定性算法（径向/网格/层级）？

2. **参数敏感性**：0.6 的斥力与 0.001 的斥力差了 600 倍，但在同样的小图上视觉效果可能从天壤之别到无明显差异。如何设计参数空间使算法对节点数不敏感？

3. **边界处理四种形态**：硬 clamp / 软边界力 / 墙壁反弹 / 缩放后拟合 — 各自的适用场景和陷阱是什么？本项目踩过了全部四种。

### 手势与坐标

4. **Canvas 变换顺序**：`translate → scale → translate(-center)` 的含义是"以某点为锚点缩放"。Flutter Canvas 变换矩阵从右到左应用。这个认知模型是否清晰？

5. **Gesture delta 语义**：`focalPointDelta` 是帧间增量（~1-3px），不是累计位移。混淆两者是最常见的手势 bug。

### 渲染

6. **`CustomPaint(size: Size.infinite)`**：它告诉 Flutter "我多大都行"，但如果父组件不约束，painter 的 `size` 可能是 0 或 inf。永远用 `LayoutBuilder` 获取实际尺寸。

7. **抗锯齿重影**：当 `shouldRepaint` 频繁触发（手势中每帧重绘），文本抗锯齿可能逐帧叠加产生"重影"效果。

### LLM 集成

8. **contextSize vs maxTokens**：contextSize 是总窗口（输入+输出），maxTokens 是输出上限。需确保 `输入 tokens + maxTokens < contextSize`。Qwen3.5-2B 原生 32K，端侧只能用 4K。

9. **Prompt 的 token 效率**：要求 LLM 输出紧凑 JSON（无换行缩进）可节省 30-50% 输出 token。格式样例比文字描述更有效。

### 架构

10. **缓存层级**：图谱缓存在内存（MindMapService._graph，L1）和数据库（conversation_repository，L2）。谁负责失效？何时 GC？和 CPU 缓存设计思想一致。
